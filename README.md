# Live Wire

A lightweight React schematic editor. Drag a component from the toolbox onto the canvas to place it (or select it and click the canvas). Components snap to a 10-unit grid when placed or moved. The drawing area starts at 1000×700 and grows to the right and down to hold what is drawn, with some room around it. When you draw a wire to the right or bottom edge, the grid grows ahead of the cursor and the view scrolls with it, so a wire can be run past the edge. It never grows left or up, so the drawing never shifts while you draw. The grid keeps its size on screen, so a larger area scrolls rather than shrinking, and SVG exports cover the whole area. The canvas shows a prompt only while an action waits for a click (drawing a wire or section, placing a part, choosing the part to connect to). When a two-terminal component is placed on top of a wire it is connected into that wire: the component is turned along the wire, centred there, and the wire is cut so both ends meet its terminals (straight horizontal or vertical wires with room for the component only; undo removes the part and restores the wire). Placed on top of another two-terminal component, a small menu offers **Connect in series with** or **in parallel with** that component, which arranges the pair like the Properties panel's series and parallel buttons. Dismiss the menu to leave the component unconnected. Shift-click adds or removes a component or a wire from the selection, so components and wires can be selected together. Right-click a component for **Connect in series**, **Connect in parallel**, **Rotate 90°** (diodes also **Rotate 45°**, for parts drawn at an angle such as a bridge rectifier; the Properties panel has the same buttons), **Change subtype** (other subtypes of its family; label, position and ratings that still apply are kept, and the BOM is offered the change) and **Delete component**. With several items selected, components of one type share those options (rotate and change subtype apply to all of them, series and parallel connect them) and the last entry reads **Delete Selection**; when the selection mixes component types, or includes wires, every option except **Delete Selection** is blocked. Right-clicking a wire offers **Delete wire** (or **Delete Selection**). Series and parallel on a single component then ask you to click the component to connect it with; with several components selected they connect the whole selection. Click anywhere within a component's area to select it, drag it to move it, and drag a corner handle of the selected component to resize it from 10% to 1000% of the standard symbol (the same size can be typed in the Properties panel; one undo reverts a resize); select one to edit its label or value (the canvas shows only reference labels such as R1, C5 or CR2; values and ratings are listed in the Properties panel and shown when you hover over a component, and SVG exports show labels only), and use the wire tool to connect points on the grid. Wires are independent drawing elements and do not move automatically with components.

Connections are marked as on a printed schematic. A dot is drawn where a wire ends on a component (on the terminal itself for two-terminal parts), where a wire ends on another wire's run, and where three or more wire ends meet; two wire ends meeting simply continue the wire and get no dot. Where a horizontal and a vertical wire cross without connecting, the horizontal wire is drawn with a small hop over the other. Dots and hops follow from the drawing itself, update as you edit, and are included in SVG exports. Ground symbols are drawn without a label.

A wire that continues on another sheet can end in an off-page arrow with a label. Right-click near a wire end for **Arrow at this end** (**Arrow out**, continues on another sheet; **Arrow in**, comes from another sheet; or no arrow) and **Label this end…**, which jumps to that end's label field in Properties. A selected wire's Properties list both ends (with their coordinates), each with an arrow choice and an end label such as "B+ to sheet 2". The arrow points along the wire and the label sits just beyond it. An end with an arrow never gets a connection dot. Arrows and labels are saved with the wire and included in SVG exports; a section export keeps them only on wire pieces that still end where the wire did.

**Ribbon cable** (toolbox category CONNECTORS, reference W1, W2…) joins circuit boards. It is drawn as a connector header on each board with parallel conductors between them, and every conductor is a pin labelled J and a number. Each pin can be wired on either side, and wires ending there get a connection dot on the pin. A new cable has 6 wires numbered after the highest J pin already used by other cables on the sheet, so J numbers continue from one cable to the next. Change the number of wires (2 to 64) by right-clicking for **Number of wires** (common sizes from 2 to 40) or in the **Ribbon wires** section of Properties. Adding wires continues the numbering after the highest pin, and removing wires drops the last ones. Properties can also renumber all pins from a first J number or set each wire's J number individually, and warns when a J number is used twice. A value still reading "N-way ribbon" follows the number of wires.

**Save project** (also Ctrl+S, or ⌘S on a Mac) saves straight to the project's file. Only a project that has never been saved, or one imported through the Import dialog, asks where to save it the first time. After that every save writes to the same file without asking; hovering the button shows which file. **Open project…** in the project menu opens a file the same way, so saving writes back to it, and projects reopened from **Open recent** remember their file too (the browser may ask once for permission to write to it again after a reload). **Save as…** always asks for a new file and continues with that file. Saving directly needs a browser with file access (Chrome, Edge or VS Code's browser). In other browsers, Save project downloads the file and Save as asks for a name to download it under.

Wires are only connected where a wire ends: on a component, on another wire, or where wire ends meet (shown with a dot). Wires that cross are not connected and the horizontal one hops over the other. When you move a component, the wires ending on it move with it and are reshaped so they stay horizontal and vertical. A wire leaving the component sideways or vertically keeps leaving it that way, with a step added where needed, and a wire with both ends on the component moves as a whole. To move a component somewhere else entirely without its wires, right-click it and choose **Detach from wires**, then drag it, or hold Alt (Option) while dragging. The wires stay where they were. Detaching applies to the next move only; choosing it again before moving (**Keep attached to wires**) cancels it.

**Test circuit** (the ▶ button in the top bar) checks whether the open circuit works. It turns the drawing into a standard SPICE netlist and simulates it with [ngspice](https://ngspice.sourceforge.io/), compiled to WebAssembly (the [`eecircuit-engine`](https://github.com/eelab-dev/EEcircuit-engine) package, MIT-licensed), so it runs entirely in your browser; nothing is uploaded. The engine is about 20 MB (6 MB compressed) and only downloads the first time you press the button. The test is a **DC operating point**: the steady state with every source constant, so capacitors count as open and inductors as shorts. It does not show how a signal changes over time.

- **Nets** come from the geometry: wire pieces that touch are one net, a wire that ends on another wire joins it, and a terminal is connected when a wire ends at it. Wires that only cross are not connected. All ground symbols are the same 0 V node; with none, the first voltage source's negative terminal is used as 0 V and the result says so.
- **Simulated parts:** resistors (all subtypes; a potentiometer with its wiper in the middle), capacitors, inductors, transformers (by their winding DC resistance), DC voltage sources (the value, e.g. `5 V`), diodes (an LED's colour in its value, such as `LED green`, sets its forward voltage; a Zener's breakdown voltage is read from its value, else 5.1 V), switches (closed unless the value says open or off), fuses, NPN/PNP transistors (a generic model; `PNP` in the value selects PNP) and the **12AX7, 12AT7 and 12AU7 split triodes** (Koren's tube model; heaters are not simulated, and results are approximate, within about 25% of data-sheet figures). Values are read as written (`1 kΩ`, `47 nF`, `4R7`, `500 mA`).
- **Not simulated yet:** the full-size tube symbols (EL84, 6L6GC and the 9-pin 12AX7 family symbols), relays and ribbon cables. They are listed in the result and left out of the simulation.
- **The result** opens in a dialog with a verdict (works, works with warnings, will not work, or can't be tested yet), a list of findings with a **Show** button that selects the part, every part's voltage, current and power, the voltage at each net (a wire label names a net; otherwise it is called after the parts on it), the netlist (**Copy netlist** to run it in ngspice or LTspice) and any messages from ngspice. **Run again** re-tests after you change the drawing.
- **What it catches:** no voltage source; a source with both terminals on the same net, or sources and inductors in a loop; unreadable values; loose ends and unconnected terminals; parts shorted out by a wire; a circuit where no current flows; an LED connected backwards or carrying more than about 30 mA (a warning above 20 mA); a resistor above its power rating (a note when it dissipates over 0.25 W with no rating set); a fuse carrying more than its rating; a polarised capacitor connected backwards; a triode over its maximum plate dissipation or with a positive grid. Wires that cannot be solved (a short circuit) are reported instead of hanging the simulator.

To connect components in series or parallel, Shift-click at least two two-terminal components, or enable **Select multiple components** and click them. Choose an arrangement in Properties; components are repositioned in selection order and reset to a horizontal orientation. Existing wires touching their terminals and any previously generated arrangement wires are removed in full after confirmation, so other branches of those wires may also be disconnected. Undo restores the previous diagram. The editor blocks arrangements that would overlap other components or retained wires.

Toolbox categories can be collapsed or expanded individually or all at once, and the choice is remembered in this browser; searching temporarily opens every matching category. The toolbox includes resistors, capacitors, diodes, NPN transistors, normally open SPST relays, triode tubes, and transformers, along with inductors, LEDs, ground, voltage sources, and switches.

Diode options include signal, rectifier, Zener, Schottky, LED, photodiode, and varactor. Signal and rectifier diodes share the standard diode symbol.

Capacitor options include ceramic, film, electrolytic, tantalum, variable, and trimmer types. Ceramic and film capacitors use the standard unpolarized symbol; electrolytic and tantalum capacitors use a polarized symbol.

Resistor options include carbon film, metal film, ceramic, wirewound, potentiometer, variable resistor, NTC thermistor, and photoresistor. Select a resistor to enter its optional power rating in watts and tolerance percentage alongside its resistance. Fixed resistors share the standard resistor symbol; potentiometers have a third, grid-aligned wiper terminal.

Schematics usually draw a dual triode as two separate triodes labelled with a section letter (V2A and V2B). The tube list therefore also has **12AX7, 12AT7 and 12AU7 split** symbols: one triode with its plate, grid and cathode pins (1·2·3 for section A, 6·7·8 for section B), plus its half of the heater: from pin 4 (section A) or pin 5 (section B) to the centre tap on pin 9, which both halves share. Choose the half with **Triode half** in the Properties panel; the pin numbers follow. The section follows the letter in the label. A BOM lists the tube once (`V2`, 12AX7), and both V2A and V2B match that row; "Detect components from BOM" proposes each section found in an import as its own triode, and a generated BOM lists the tube once. A BOM that already lists `V2A` and `V2B` separately also works. Label reading enlarges the image as well, which helps with the small text of low-resolution scans; very small or blurred labels can still be missed, so add those by hand or by clicking the label.

The **Transformers** category offers a generic **Transformer**, a **Power transformer** (PT), an **Output transformer** (OT, push-pull), a **Single-ended output transformer** (OT, no centre tap) and an **Interstage transformer**, each with its own symbol and references (T1, PT1, OT1). The power transformer has a primary, a centre-tapped high-voltage winding and a heater winding; the output transformer has a primary with a centre tap (outer ends to the tube plates, centre tap to B+) and a secondary for the speaker; the interstage (driver) transformer has a centre-tapped secondary for a push-pull pair. Each kind carries its own characteristics, edited in the Properties panel, stored with the circuit and included in the BOM (a column appears only when a component uses it): power transformers have **primary voltage**, **secondary voltages**, **frequency** and **power rating**; output transformers **primary and secondary impedance** and **power rating**; interstage transformers the two impedances; all kinds **primary and secondary DC resistance**. Below the fields a **Transformer characteristics** list shows the kind's windings and which terminals they are on, what follows from your values (an output transformer's turns ratio, voltage and current at full power; a power transformer's full-load primary current, to choose the mains fuse) and typical values for the kind. Right-click → **Change subtype** switches between kinds and keeps the characteristics they share. The **Transformer catalog** section of the toolbox lists known transformers (currently Peavey 70500211, Peavey 29231, Hammond 125ESE and Hammond 291AEX): drag one onto the circuit, or click it and click the canvas, and you get a transformer of the right kind with the part's value and characteristics already filled in. For a transformer already on the circuit, the **Known transformer** list at the top of its details switches it to a catalog part (keeping its label, position and size; the BOM is asked about differences like for any edit). A part from the catalog also shows its notes (taps, DC bias, which amplifiers it fits) and a link to where the figures come from. Only published figures are filled in: the Peavey 70500211 has no published primary impedance or winding resistance, and the Peavey 29231 (the Classic 50 power transformer) takes its voltages from the Mercury Magnetics replacement P-CL50-P-240 but has no published currents or winding resistances, so those fields stay empty for you to fill in. Typing a catalog part number such as `Hammond 291AEX` or `705-00211` as a transformer's value is enough to show its notes. New parts are added to the list in `src/circuit/transformerCatalog.js`. In **Test circuit** a transformer is simulated by the DC resistance of its windings (typical values are assumed, and said so, unless you enter them), which is what puts the output transformer's primary resistance in the plate supply; the windings are not coupled at DC, so signal transfer is not modelled. A winding with neither end wired is ignored; one end wired is reported as a loose end.

The **Fuses** category offers a generic fuse, glass and ceramic cartridge fuses, blade fuses, resettable (PTC) fuses, and thermal fuses, each with its own symbol. Enter the current limit as the component's value, then optionally its voltage rating, dimensions (pick a common size such as 5×20 mm or 6.3×32 mm, or type your own), and, for cartridge and generic fuses, the blow characteristic: very fast (FF), fast (F), medium (M), slow (T), or very slow (TT). Cartridge fuses show the chosen letter on their symbol, and the characteristics appear under the component, are saved in SVG and project files, and can be series/parallel arranged like other two-terminal parts. In a BOM they use optional `Voltage`, `Size` (or `Dimensions`) and `Speed` (or `Blow`) columns, which are written only when a fuse uses them; "Slow blow", `T` and "time-delay" are all read as slow blow. BOM rows with an `F` reference are typed as fuses, and wording such as "AGC", "blade" or "resettable" picks the subtype.

Tubes and valves are the same component (the category is labelled "Tubes · Valves", and searching for "valve" finds them). Tube types are also known by equivalent names, which Live Wire treats as the same type in the toolbox search, in a BOM's Type, Value and Description cells, and when matching triode sections to a BOM row: EL84 = 6BQ5, 7189, N709, 6P14P; 12AX7 = ECC83, E83CC, 7025, 6681, B759, CV4004; 12AT7 = ECC81, E81CC, 6201, B309, CV4024; 12AU7 = ECC82, E82CC, 5814, 6189, B329, CV4003; 6L6GC = 5881, 6L6WGC, 6L6GB, 6L6G, 6L6, 6P3S. Grade suffixes (12AX7A, ECC83S) are recognised too. These are the usual interchangeable names but not always identical parts (a 6L6G is rated lower than a 6L6GC, and "premium" types such as 5814 or 7025 are selected grades), so check the tube against your amplifier's service data before substituting. Selecting a tube shows a **Tube characteristics** table in the Properties panel: amplification factor (μ), plate voltage, plate current, plate resistance, transconductance, grid bias voltage, maximum plate dissipation, heater, and equivalent names (plus screen grid voltage and dissipation for the EL84 and 6L6GC). A split triode shows its whole tube's data, and a generic Tube whose value names a known type (for example ECC83) shows that type's data. The values are typical figures from manufacturer data sheets and vary between makers and variants; the data lives in `src/tubeData.js`. Tube options include EL84, 12AX7, 12AT7, 12AU7, and 6L6GC. Their numbered terminals show the electrodes and heater connections; the dual triodes include both sections and the heater center tap. The EL84 symbol also marks socket positions 1, 6, and 8 as not connected. The 6L6GC symbol shows the six connected pins; octal positions 1 and 6 are unused or absent on the referenced base. Check the datasheet for the particular tube before wiring, since construction can vary.

Pinout references: [Sovtek EL84](https://media.tubetown.net/info/datenblaetter/tubes/sovtek/soel84.pdf), [GE 12AX7](https://w140.com/tekwiki/images/5/5e/GE_12AX7_data_sheet.pdf), [12AT7](https://tubes.mit.edu/6S917/_static/2026/resources/12AT7.pdf), [Brimar 12AU7/ECC82](https://brimaruk.com/BrimarUK/wp-content/uploads/Brimar-ECC82-DataSheet.pdf), and [RCA 6L6GC](https://www.frank.yueksel.org/sheets/093/6/6L6GC.pdf).

Use **V** for selection, **W** for wiring, **Delete** to remove a selection, and **Ctrl/Cmd+Z** (or **Shift+Ctrl/Cmd+Z**) to undo or redo. Export downloads the current drawing as an SVG. Designs are kept in memory unless saved as a Live Wire project.

### Tidying a crowded circuit

Two buttons at the right of the canvas toolbar help when a circuit gets hard to read. Both can be undone, like any edit.

- **Optimize labels** gives every reference (R10, C8…) a place of its own, directly next to its component and clear of other parts, wires, wire labels and labels. A label has to read as its own component's: it is put where it is nearer to that than to any other part, which is what keeps C8 from looking like R10's label. Where room is short a label is made smaller (down to 7 px) and as a last resort it still crosses a wire rather than another part. The notice says how many labels were unclear before and after. A label's place is kept with the component and saved with the circuit; turning or resizing a component puts its label back in the default place (run **Optimize labels** again to place it).
- **Rearrange components** moves the components across the grid so that fewer wires cross (every crossing is a hop to read past), wires are shorter and bend less, and components keep clear of each other. It works on the whole circuit (not in a linked section) and runs in the background for a few seconds. Components only move; they are never turned, resized or reconnected: the circuit is checked to be wired exactly as before, and if a rearrangement cannot be shown to be, nothing is moved. Wires that have to follow are drawn again as horizontal and vertical runs. When it is done the labels are optimized too, and a bar at the bottom of the canvas reports the result (components moved, crossings before and after, wire length) and asks whether to **Keep** or **Revert** it. Reverting restores the circuit as it was (Redo brings the rearrangement back); changing anything else counts as keeping it. If nothing better is found you are told so and nothing changes. The result is a better starting point rather than a finished layout: wires that run together in bundles, such as those on a ribbon cable, can only be untangled by hand.

## Importing circuits

Import PDF, PNG, or SVG files locally; files are not uploaded. Select one or more PDF pages (up to 25 per import); each becomes a separate sheet with its own undo/redo history. The existing drawing remains on its original sheet. The active sheet is exported to SVG.

All pages of a PDF (up to 25) are selected by default, so a multi-page schematic becomes one project with a separate circuit for each page; the project is named after the file. The import dialog's **Add the circuits to** choice adds them to the current project or starts a new one (replacing the current circuits and BOM after a confirmation). An untouched starter circuit is replaced automatically. Splitting a single page into several logical circuits is not available yet.

The circuits of a project are shown as portfolio tabs with a folded corner under the top bar (linked section views are in italics). Click a tab to open that circuit, or use the **‹** and **›** buttons, which also show your position (for example 3 / 5); with a tab focused, the arrow keys, Home and End move between tabs. The tab strip scrolls when there are more tabs than fit. Right-click a tab (or press Shift+F10 or the menu key on it) for **Rename…** (also F2 or a double-click; Enter saves, Escape cancels), **Duplicate circuit** (a copy with its own drawing, edit history and BOM rows; on a linked section, **Duplicate view**), **New circuit after this**, **Move left** / **Move right**, **Export SVG**, **Clear circuit** and **Delete circuit**. Deleting a circuit also removes its linked section views and BOM rows after confirmation and cannot be undone; on a linked section **Delete section view** removes only that view. The last remaining circuit cannot be deleted.

The **File** menu has **New circuit** (adds an empty circuit to the project) and **Clear circuit** (removes everything drawn on the current circuit but keeps its reference image; undo restores it).

The arrow beside the project name opens the project menu: **New project** (starts an empty project), **Open project…** (a `.spark` project or single-circuit file, replacing the current project), **Open recent** (the last 8 projects you saved or opened, with the date and size, and **Clear recent projects**), **Rename…** (edits the project name in place), **Save project** and **Save as…** (asks where to save the project as a new file). Before New project, Open project or Open recent replaces the current project, it is kept under Open recent so nothing is lost; if that fails you are asked first. Recent projects are stored in this browser's IndexedDB with their full contents and never leave the machine; reopening a recent project with the current name restores its last kept version after confirmation.

When importing a circuit, **Search for a bill of materials** checks the selected PDF pages or the imported image for a table in the same document. Unselected PDF pages are not searched. Text is read locally; image pages and PDF pages without a detected text table use local OCR, which can take time. Enable the additional OCR option to also search images on PDF pages where a text table was already detected. The search is heuristic and can miss or misread tables; disable it if you want to import without searching.

If possible tables are found, the BOM dialog opens after the circuit import. Choose a table and its circuit, review and correct the editable preview, then explicitly import or dismiss it. Other detected tables remain available when reopening **BOM** during the session. To combine tables for one circuit, opt to add detected rows instead of replacing that circuit's entries; duplicate references must be resolved first. Tables continuing onto a page without repeated column headings may be missed. A BOM on a separate selected PDF page is not automatically associated with another sheet; choose the appropriate circuit yourself. Detection does not automatically identify circuit symbols or connections.

Live Wire SVG exports include editable circuit metadata and can be reimported with their component types, values, wires, and reference image intact. Only the metadata is used when restoring an editable SVG. Previously exported Spark SVGs with editable metadata remain compatible; older SVGs without it and other SVGs are treated as images. SVGs containing scripts, external references, unsupported elements, or a document type declaration are rejected.

For PDF, PNG, and SVGs without editable metadata, the importer provides a reference image and optional experimental detection of horizontal and vertical straight wires. Detected wires may be missing, misplaced, or mistaken for parts of symbols or text. Check and correct each one. Select a wire to edit its optional visual label; the label does not create an electrical net.

On an imported sheet, choose **Teach & review** to mark missing components and straight wires at the reference image's resolution. Scroll and use **Image zoom** (10% to 500%, keeping the middle of the view in place) to see details. Drag a box tightly around a symbol (or click two opposite corners), choose its component type, subtype and orientation, optionally enter its label, then choose **Save mark & add**. For a wire, drag along its center or click its two endpoints. The mark creates an editable circuit element and a local training example. Adjust positions, rotations, labels, values, and connections afterward; a component added from a marked symbol is sized to match that symbol, and components placed afterwards (from the toolbox or from BOM detection) take the typical size of those already matched to the reference. Change any component's size in **Properties → Size**. The canvas zoom runs from 10% to 500%; when the drawing or reference is larger than the view, scrollbars let you move across it, and zooming keeps the middle of the view in place. Undo removes the element, but does not remove its training example.

Choose **Find similar components** on any imported sheet to compare its image with saved component examples. Review the numbered boxes, then add or dismiss each suggestion. Adding a suggestion also saves it as an example. Suggested components receive a placeholder label, not a recognized reference. This is limited visual template matching, not a general trained model: it searches at the example's image size and orientation, can miss or misclassify symbols, and cannot infer labels, values, pins, or connectivity. Manual wire examples adjust the brightness and minimum length used by straight-wire detection on **future imports**; they can increase false positives. No wire or component match proves an electrical connection.

**Run detector experiments** adapts the fixed-metric, keep-or-discard idea from [autoresearch](https://github.com/karpathy/autoresearch) to this local template matcher; it does not run autoresearch's language model or an autonomous coding agent. Mark components on at least two different images as **Training**, and mark at least one non-component patch (for example text or crossing wires) as **Training**. On a separate image, mark at least one component and one non-component as **Validation**. Choose **Not a component** to save a negative patch without adding an element. Use representative, independently sourced images: the app prevents using the same reference image in both sets, but cannot recognize a re-encoded or cropped copy of the same document. Older component examples without image identities remain usable for ordinary matching, but must be cleared before the first experiment because their source cannot be separated from validation.

The experiment compares a fixed range of similarity thresholds using training patches with each image held out in turn. It saves the selected threshold and a snapshot of the training templates only if the held-out validation patch F1 improves over the comparison detector; otherwise it keeps the existing detector. The first comparison uses the current training templates at the default threshold; later comparisons use the saved detector. The reported metric measures classification of marked, normalized patches, not detection or localization across whole scans, and a small or unrepresentative validation set can be misleading. Repeated experiments against the same validation images can also overfit them. Review all suggestions. Once a detector is saved, **Find similar components** uses its snapshot; newly marked examples take effect in that detector only after a later experiment improves validation. Validation examples are never used as templates. Wire detection is not optimized by this experiment.

Up to 50 examples are stored only in this browser's local storage; they can contain small pieces of the scanned image. Browser storage is tied to the address and port, so examples saved on a previous port are not available on port 1343. They are not included in SVG or `.spark` exports, synced to other devices, or sent to a server. Clearing browser data removes them. Use **Clear examples** to delete all examples and the optimized detector without changing circuit elements. Hide or remove the reference when finished; removing it can be undone. A visible reference appears in the SVG export; even when hidden, it remains in the editable metadata until removed.

Files are limited to 30 MB, images to 50 megapixels, and PDFs to 1,000 pages. Use **Save project** to download a `.spark` file containing all circuits and linked views, then import it to restore them. Live Wire retains the `.spark` format for compatibility with existing projects. Undo history is not saved. Projects over 30 MB cannot be reimported; export individual sheets instead.

## Bill of materials

The bill of materials is a tab of its own at the end of the sheet bar, next to the circuits (the **BOM** button opens it). It lists one row per part, with its properties in a table you can edit: Value, Voltage, Wattage, Tolerance, Description, any other rating a part in the project uses (voltage, fuse speed, transformer figures…) and extra columns of your own (**Add column**). Edit a cell and press Enter (Escape undoes the typing). Changing a value or a rating also changes the part in its circuit, as an edit you can undo there; a rating a part does not have (a capacitor's wattage) is greyed out. Capacitors have a voltage rating and a tolerance, resistors a power rating, a tolerance and a voltage rating; set them in the component's properties or in the BOM. A column you add under the name of a built-in one (such as Voltage) is merged into it. A filter and a circuit selector narrow a long list, and a banner says when components are not in the BOM yet (**Add them**) or BOM rows have no component, which are highlighted and can be deleted one by one (**Remove** on the row) or all at once (**Remove them**). **Generate from circuits** lists the components of all circuits again, keeping the descriptions and extra columns of parts already listed. A BOM names its parts by reference, so if a circuit uses one reference for two parts (two C1s) you are shown the rename it needs (the second becomes the first unused reference of its kind, such as C5) and asked before anything is changed; triode sections (V1A, V1B) sharing a reference have to be fixed by hand. **Import / export…** opens the dialog to import a CSV, XLSX, or PDF BOM or export the table as CSV or XLSX; in the dialog you can also edit the table before importing it. BOMs are saved in `.spark` projects. Each reference is matched case-insensitively within its circuit, so different circuits can have their own R1. Select the default circuit for files without a Circuit column, or use the circuit names shown in the dialog in that column. Importing replaces BOM entries for the circuits present in the table; other circuits' entries are retained. Linked sections share their parent circuit's BOM.

The table requires a Reference, RefDes, Designator, or Label column. Multiple references can be comma-separated in a cell. Optional columns include Type (a toolbox type or name), Value, Wattage, Tolerance, and Description. Other named columns are retained as additional specifications. Correct cells, headings, and rows in the table, or switch to CSV editing. Review OCR results carefully: characters, rows and column boundaries may be wrong or missing, and invalid or duplicate references must be corrected before import. Scanned parts lists with repeated side-by-side columns can be detected even when only the first column has headings. Standalone PDF imports search all pages and offer detected tables for review; OCR may take time. **Use OCR for all PDF pages** also scans pages with detected text tables. BOM PDFs are limited to 25 pages and 50 megapixels per rendered page. XLSX imports allow selecting a worksheet. CSV exports prefix formula-like cells with a tab for spreadsheet safety; XLSX exports write text as strings.

After import, confirm whether to apply matching BOM specifications to existing components. In **Teach & review**, **Detect components from BOM** reads the image with local OCR and proposes a component for every BOM reference it finds (R1, C3, CR5…) that is not already in the circuit. The component type comes from the BOM's Type column, else from the reference prefix (R, C, D, CR, Q, K, L, T, SW), else from a tube named in the value or description (for example EL84 or 12AX7); references with no known type are reported and skipped. Each proposal is placed on the nearest symbol that matches a component you marked earlier, else where earlier assignments put symbols relative to their labels, else at its label, and takes its value, wattage and tolerance from the BOM. **Add all trusted matches** adds every proposal whose OCR text equals a BOM reference or is a misread you corrected before; other near matches (such as `CRS` for `CR5`) are accepted only when exactly one BOM reference is that close and must be added one by one. A near match must also look like OCR noise: a changed prefix letter has to be one OCR really confuses (`A` for `R`, `K` for `R`, `G` for `C`…), and text without a letter prefix (such as `.022`) is never a reference. Jumper and test-point labels (`J58`, `JP3`) are mostly not in the BOM, so a label of that shape that is not a BOM reference is treated as a jumper: it is never turned into the part with the same number (`R58`), and the detection summary lists how many jumper labels were left out. The manual **Find BOM labels** list stays permissive so you can still pick any close candidate yourself. Columns of closely spaced references that look like a BOM table are ignored. Resistors, capacitors, diodes, fuses and other two-terminal parts are turned to match the drawing: a matched symbol keeps its own rotation, otherwise the straight leads around the label are examined (text the OCR read is ignored) for a part lying flat or standing upright. On the Classic 50 schematic this agreed with a manual reading for about 90% of parts (53 of 59), so check the rotation of each part and use right-click **Rotate 90°** to correct it. Diodes drawn on a diagonal, as in a bridge rectifier, are turned 45°; which end is the cathode is not read, so check polarity of diodes and electrolytic capacitors. Tubes keep the toolbox orientation. Detected parts are sized to the drawing: a matched symbol sets the size, else parts already sized on the sheet, else an estimate from the height of the drawing's reference labels (a two-terminal symbol is about 2.6 label heights long, a tube about 13.5, measured on the Classic 50 main board). The BOM's wording also refines the type found from the reference prefix: `LYTIC`, `LYT.`, `LY.CAP`, `EL-AX` or `RAD PC` makes an electrolytic capacitor, `CER`, `CD-`, `MON` or `T/C` a ceramic one, `MYLAR` a film one, `WW` a wirewound resistor, and `ZENER`, `1N400x`/`1N540x` or `RECTIFIER` a zener or rectifier diode. Such a subtype describes one part, so when it is learned for a reference it does not change the prefix's meaning for other parts. Move each added component onto its symbol and connect it yourself: OCR can miss or misread labels, and connectivity is not inferred. **Find BOM labels** instead lists every close match so you can choose **Use label**, verify the type, and mark the symbol yourself.

To teach the app, open **Teach & review** with a BOM: the image text is read once and reference-like text is highlighted. Click a label, confirm or change its **BOM reference** (the list shows each reference's value and whether it is already placed), set the component type if the suggestion is wrong, drag a box around its symbol, and choose **Save mark & add**. Without a symbol box, **Teach label & add** still teaches the reference and places the component at the expected symbol position. Each assignment is stored in this browser and used on later imports: the marked symbol becomes a template example of the BOM's component type; the typical symbol position relative to its label (in label heights) places future components; the type chosen for a reference prefix (for example `VR` as potentiometer) is applied to BOM rows without a Type; and OCR misreads (for example `S` read for `5`) are matched to the right reference. The newest 200 assignments are kept, and **Clear examples** also clears them. Learned positions and types are guesses from a few examples, so always review the proposals. OCR, spreadsheet, and PDF processing run locally; OCR assets are served by Live Wire rather than a third party.

### Text recognition (OCR)

Live Wire reads text with PaddleOCR's PP-OCRv5 models (Apache-2.0: the mobile text detector and the English recogniser, about 12.6 MB in `public/ocr/`) running through onnxruntime-web (WebAssembly) in a browser worker, so nothing is uploaded. The detector finds text at any position and the recogniser reads each line, which suits schematics: tiny labels, values such as `47K`, `1k5`, `.02` or `0.01uF`, and tube names (`12AX7`, `V2A`). Tall text regions are read rotated both ways and the more confident reading is kept, so vertical labels work; each word has an `orientation` of 0, 90 (reading upwards) or 270 (reading downwards). BOM table scanning uses horizontal text only. On the sample amplifier schematics this reads roughly twice as many values as the previous Tesseract engine, and finds vertical text it could not read at all. It still misses or misreads some text, especially in poor scans and where lines touch the lettering.

In **Teach & review** the text is read as soon as the image is shown, with or without a BOM. When you mark a resistor or capacitor, the closest text beside the symbol that reads as a value of that kind is used as its value (`1k5` becomes 1.5 kΩ, `.02` becomes 0.02 µF, `220 μμ` becomes 220 pF, `20/450` becomes 20 µF). Resistances must be standard values (E24, plus 2.5 and 5 for potentiometers) so misreads such as `22K3` are ignored; a BOM value always wins. Check every value: it can come from the wrong label.

When editing a matched component's value, wattage, or tolerance, finish the field with Enter or by leaving it. If it differs from the BOM, approve updating the BOM or cancel the circuit edit. Undo and redo also request approval when they would change a matched BOM specification. The original imported file is not modified; export a new CSV or XLSX to save changes separately. Generating a BOM replaces the current BOM and requires valid reference designators; ground symbols are excluded. **Clear BOM** removes the BOM without deleting components.

## Linked sections

Choose **Create linked section**, click two opposite corners around a stage, and name it (for example, Preamp or Power amp). Switch between the original and sections using the tabs. These are rectangular views of the same circuit: edits, deletions, and undo/redo are shared, including wires that extend beyond a section. Removing a section view does not delete circuit elements.

Sections are defined by the user, not inferred from circuit function. Live Wire does not automatically identify amplifier stages or reconstruct connectivity from a scanned schematic; the reference, learned suggestions, and experimental wire detection still require manual review and tracing.

Exporting a section creates a standalone SVG containing components whose centers lie inside the selected rectangle and wire segments clipped to it. Its reference image is cropped to the same rectangle. Connections crossing the boundary are cut in the exported copy, so check them manually; Live Wire does not infer or label off-sheet nets. Reimporting that SVG creates a separate circuit, not a live link to the original. Export the original separately to retain the complete circuit.

## Development

Run `npm install`, then `npm run dev` and open http://localhost:1343. Development and preview servers use port 1343 and report an error if it is occupied. Use `npm run build` for a production build, `npm run lint` to check the source, and `npm test` to run the tests (Node's built-in runner; the simulator tests run the real ngspice engine). The code is organised in layers that lint enforces; see [ARCHITECTURE.md](ARCHITECTURE.md) before adding a module.
